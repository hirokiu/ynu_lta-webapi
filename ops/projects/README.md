# 小規模なプロジェクト分離の検証

同じソース・同じAPI/Webイメージを使い、プロジェクトごとにCompose名、MongoDBボリューム、ネットワーク、認可設定を分ける方式の試作です。既存Proto/Devへの適用や新環境の公開は行いません。

## 設定の生成

`python3 ops/projects/render.py lab-alpha /tmp/kirokun-lab-alpha --port 18091`

別ID・別ポート・別出力先でもう一組生成します。出力は未稼働のひな形です。既存ディレクトリは上書きしません。`.env.example` の確認済みイメージ、Firebase設定、権限を運用者が設定し、Settingsを初期化してから公開判断します。秘密鍵と利用者データはコピーしません。通知と配信準備は初期状態で無効です。

## 分離テスト

依存パッケージを導入済みの開発用Macで `bash ops/projects/smoke.sh` を実行します。Dockerが必要です。127.0.0.1の37031/37032番と専用名kirokun-lab-a/bを使い、終了時にテストコンテナーとボリュームを削除します。実利用者のデータは使いません。

実際のAPIルート・認可処理を通し、別プロジェクトの利用者による閲覧・設定変更の拒否、同名ユーザー・同一Survey IDの分離、所属先ごとの権限、表示設定の独立性、Host等によるDB切替の防止を検証します。Firebaseのトークン検証だけは固定のテスト用IDに置き換えています。実Firebase、通知、ブラウザー画面、アプリを通した統合試験ではありません。

## 次段階

- 管理画面は同じ成果物を各環境へ配置し、コードのコピーを個別改修しない。
- データ分離は専用DBを前提とする。同一DBでの複数プロジェクト収容を保証するものではない。
- アプリの任意プロジェクト選択、公開/非公開一覧、所属管理、プロジェクトを識別する通知は別途実装が必要。
- Firebaseを共通化する場合、アカウント削除・資格情報変更が他プロジェクトへ影響しない運用と共通の本人管理が必要。今回の試験はFirebase利用者を変更しない。
- 現在の新サーバーはメモリー約2GB。環境の追加公開前に容量を評価する。検証用MongoDBのバージョンは現行互換用であり、今後の新規基盤の推奨バージョンを示すものではない。
