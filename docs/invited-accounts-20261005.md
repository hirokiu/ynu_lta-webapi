## 今回の実装（未デプロイ・既定で無効）

`USERNAME_ACCOUNTS_ENABLED=true`、`AUTH_MODE=uid`、`ACCOUNT_SCOPE` が必要。既存環境で自動的に有効にはならない。

- 管理画面Usersから回答者の招待リンクを作成する。7日有効、256ビットの乱数、DBにはSHA-256のみ。期限と状態の条件付き更新で一度だけ使用可能。リンクはURLフラグメントを使い、登録画面読込後はアドレスバーから除く。招待の自動送信は行わない。
- 管理者認可は既存UID対応表による。新規回答者を管理者に昇格させるAPIはない。
- DBの既存userId、既存UID対応表、Firebaseに残る旧メールの利用者名を予約扱いにし、新規招待への使い回しを拒否する。
- 新規アカウントは不変のランダムUID/userIdを持ち、ログイン名は別フィールド。データAPIはメールではなくUIDから利用者IDを解決する。
- パスワード登録はNode標準scrypt（N=32768,r=8,p=3、ランダムsalt、64バイト）を使用。平文保存・ログ出力なし。照合後にFirebaseカスタムトークンを発行する。
- Googleのみの新規登録も可能。招待に対応する一時FirebaseセッションでGoogleを紐づけ、UIDとGoogle providerをサーバーで確認して有効化する。未有効のUIDはデータAPIで拒否する。既存管理者の移行ではこの一時セッションを発行せず、先に新パスワードを設定する。
- ログイン後のGoogle連携はFirebaseのlinkWithPopupを使い、同じUIDを維持する。別UIDに登録済みのGoogleアカウントは自動統合しない。
- ログイン名＋scopeの一意制約、UID/userIdの一意制約、DBベースの試行制限を追加。現段階は単一環境内の登録であり、マルチラボの権限分離を実装したものではない。
- 既存メール形式のWebログインは維持する。新ログインはメールなしでもデータAPIへ接続できる。

## 招待の取消・再発行（2026-10-05 追加）

管理画面の招待ページから、未登録の新規招待をユーザー名で指定し、再発行または取消できる。操作前に確認を表示する。登録済みアカウントと既存研究者の移行招待は対象外。取消した名前は保留され、再利用しない。

再発行では招待秘密値に加えて未登録用の Firebase UID と内部 userId を新しくする。旧 Google セッションが後の登録先に接続できないようにするためである。旧 Firebase ユーザー自体は削除しないが、データ API に許可されるアカウントとの対応がなくなる。取消と登録が競合した場合は条件付き更新で一方だけが成立する。実データや既存 Firebase アカウントの変更は実行していない。

ローカルの隔離 MongoDB と Firebase モックで、権限不足の拒否、旧リンク無効化、旧 UID のアクセス拒否、登録済み招待の取消拒否、取消後の登録拒否を検証した。API と Web のビルド成功。実 Firebase とブラウザーでの操作確認は未実施。パスワード再設定とアプリ対応は未実装のまま。公開環境では引き続き機能無効。

## 回答者のパスワード再設定（2026-10-05 追加）

招待ページでユーザー名を指定し、再設定リンクを発行できる。発行者自身が招待した登録済み回答者に限定し、移行研究者・未登録・無効アカウントは拒否する。本人確認とリンクの本人への共有は研究者が行う。メールの自動送信は実装していない。リンクは1時間・1回限り、再発行で旧リンクを失効。秘密値はDBにハッシュのみ保存し、URLフラグメントから読んだ後に履歴から除去する。

再設定は条件付き更新でアカウントを recovering にして、Firebaseの更新トークンを失効させた後、新パスワードのハッシュを保存して active に戻す。UID・回答データ・Google連携は変更しない。古いカスタムトークンが後から交換されても使えないよう、credentialVersion を増分し、API側で照合する。

Firebase失効処理または最終DB保存に失敗した場合は recovering のままとし、アクセスを拒否する。自動的に active に戻してはいけない。公開前に、この障害からオペレーターが状態を確認して安全に再設定をやり直すツールと、研究者自身の復旧経路を追加する必要がある。現在の実装だけでは運用開始不可。

隔離したMongoDBとFirebaseモックで、権限・発行者制限、再発行、同時実行の単一成功、期限切れ・再利用拒否、旧パスワード拒否、新パスワード成功、旧カスタム認証の拒否、失効障害時のアクセス拒否を検証。API/Webビルド成功。実Firebase・ブラウザーQA・アプリ対応は未完了。公開環境と実アカウントへの変更なし。
